# DSH 人类记忆系统（Human Memory）实现思路

> 抛砖引玉之作：本文与配套代码只是把「遗忘曲线赋予 AI」这个想法落成第一版，架构与参数都还粗糙。已开源，欢迎 bug 反馈与改进建议。

## 1. 项目目标与定位

给 DSH（DeepSeek Harness）赋予一套受认知科学启发的「人类式记忆」。核心理念不是「全量存储、平等检索」，而是模拟人脑的**分层存储、选择性遗忘、间隔重复**：重要的记得牢、无关的慢慢淡忘、关键时刻靠「主动回忆」调取出来。

定位是一个 **DSH 本地插件**：

- 记忆全部存在本地（单个 JSON 文件），不联网、不依赖云端数据库。
- 因此不存在「集成外部开源记忆引擎 / 改造远程 RAG / 深度集成第三方」等多方案取舍——只有一条路：**在 DSH 插件模型内，用本地文件 + 一套评分公式实现**。

两条经典认知规律直接决定设计：

- **遗忘曲线（艾宾浩斯）**：新内容「先快后慢」遗忘 → 决定记忆的**时间维度**。
- **内容因素**：有意义、有结构、具体、自我相关、独特、有情绪、**停留久**的内容更易留存 → 决定记忆的**质量维度**。

## 2. 核心设计原则：遗忘 = 降低可访问性，而非删除

一句话：**用「多因子加权的检索分数」模拟记忆的可访问性，而不是物理删除。**「遗忘」在 AI 里不意味着删数据，而是降低这条记忆检索时的排名，让它「想不起来」。

由此直接回答一个关键问题：

### 问题 1：随时间衰减，是否意味着每天要主动更新记忆？能否实现、如何实现？

**能实现，而且不需要每天更新。** 做法是**惰性计算（lazy decay）**：

- 存储时只记下两个「锚点」：创建时间 `createdAt` 和最后一次被强化/访问时间 `lastAccessedAt`。
- **从不在后台批量刷新**。衰减值只在「读取这条记忆」的瞬间，用 `now - lastAccessedAt` 现算出来：

```
强度 S(m, now) = Importance(m) · exp( -( age / τ )^c )
```

- `age = now - lastAccessedAt`，`τ` 是衰减速度，`c` 是曲线形状（`c<1` 即经典的「先陡后缓」艾宾浩斯形状）。

这样，一条记忆哪怕躺了 30 天没被碰过，也**没有任何每日任务在更新它**；只有当它被检索时，才按当前时间算出它已经「忘掉了多少」。这正是人脑的运作方式——你不去想一件事，它就悄悄变淡；一想起来，才「刷新」了它。

## 3. 分层记忆架构

不把所有对话塞进一个库，而是按目录分四层（全部持久化）：

| 层级 | 功能 | 类比 | 存储策略 |
|------|------|------|----------|
| 工作记忆 `working` | 精确操作：改了哪个文件、跑了哪些命令 | 便签 / 白板 | 低权重（默认 0.05）、短寿命（TTL 24h，不设条数上限），自动清理 |
| 情节记忆 `episodic` | 每轮「做了什么」的提炼摘要 | 日记本 | 存摘要 + 会话/轮次/时间戳，正常权重 |
| 语义记忆 `semantic` | 提炼出的事实、偏好 | 个人档案 | 由情节记忆「巩固」而来（如「用户偏好 Python」） |
| 核心记忆 `core` | 极重要、永久保留 | 保险箱 | 高重要性阈值，几乎不遗忘 |

目录 `memories/` 下对应：`working/`、`episodic/`、`semantic/`、`core/`。

### 工作记忆 vs 情节记忆：分工

> 需求：精确记录（改了什么文件、跑了哪些命令）归工作记忆；情节记忆着重「提炼做了什么事」。

| 维度 | 工作记忆 `working` | 情节记忆 `episodic` |
|------|-------------------|---------------------|
| 记录什么 | **精确操作**（文件路径、命令） | **提炼**「这一轮做了什么」 |
| 权重 | 极低（0.05），快速淡忘 | 正常，参与遗忘曲线 |
| 寿命 | 短（TTL 24 小时、不设条数上限） | 长（除非被巩固归档） |
| 检索 | 参与召回 / 复习 / 巩固（按相对保留率到期） | 参与时间线与巩固 |

这正是对人类记忆的模拟：**细节先忘，留下的是「做过什么」的概括**。

> 0.1.3 起进一步引入「粒度（gist/detail）」「情绪 facet」「多 facet 存储」与 `node:sqlite` 索引，详见 [设计-记忆类型与数据库.md](./设计-记忆类型与数据库.md)。
>
> 0.1.4 起进入「重构底座 + 人格串联」：分布式用 `eventId/cues` 串起来，回忆变成读时重构（情景/语义/情绪/程序/自传体），人格参数网参与取材。详见 [设计-重构与人格.md](./设计-重构与人格.md)。

## 4. 遗忘与记忆强度的数学公式

检索一条记忆的最终排序分：

```
Score(m, q) = α · Relevance(m, q) + β · Strength(m) + γ · Importance(m)
```

- **Relevance（语义相关度）**：查询 `q` 与记忆 `m` 的匹配度。初版用字符 n-gram 的 Jaccard 相似度（中文按单字 + 双字组切分），未来可替换为 embedding 向量。
- **Strength（记忆强度，含时间衰减）**：见第 2 节，是「遗忘曲线」的落点。
- **Importance（内容重要性）**：见第 5 节，是「内容因素」的落点。
- `α、β、γ` 权重全部放在 `settings.json` 里，用户可改。

## 5. 内容重要性评分（六维，含「记忆时长」）

写入记忆时计算重要性（0–1），六个维度加权求和（权重可配置）：

| 维度 | 含义 | 可定义形容 |
|------|------|-----------|
| 自我相关度 | 涉及用户目标/偏好/身份 | 能改写成「这和我某次经历/目标的关系是…」 |
| 因果/结构 | 含「因为…所以…」「先…再…」 | 能说因果链或步骤流程 |
| 具体性 | 含可指认的人名/地点/数字/事件 | 5 秒内能画简图或指认真物 |
| 独特性 | 全新、与已知差异大 | 同组每项有 ≥2 个区别特征 |
| 情绪强度 | 带强烈情感色彩 | 高兴/生气/害怕/重要 |
| **记忆时长** | 在同一件事上停留的时间 | 停留越久，记忆越深 |

### 补充：记忆时长（dwell time）

> 之前漏了这一项：一个人在同一时间、同一件事上花的时间越久，对该事件的记忆越深刻。

实现为一个**饱和函数**：

```
dwellFactor(dwellMs) = 1 - exp( -dwellMs / dwellRefMs )
```

`dwellRefMs` 是可配置的参考时长；停留时间达到该值后，时长分 ≈ 1。同一件事被「再次提起」时，停留时长**累加**到已有记录上，而不是覆盖。

## 6. 间隔重复与间隔效应

仅有遗忘不够，必须靠「再次提起」对抗遗忘。这里有两个叠加的机制：

### 机制 A：再次提起 = 加深记忆（对应「同一事件被反复提起应加深记忆」）

每次 `memory_write` 写一条**内容相同**的记忆（或用户再次强调某个要求），不新建记录，而是对原记录做**强化**：

- `mentionCount += 1`
- 重要性分数上调
- `lastAccessedAt = now`（重置时间衰减锚点，让曲线「回升」）

### 机制 B：间隔效应（对应「间隔越长，加权越高」）

> 人类的规律是：短时间多次提起，记忆程度不如间隔一段时间后再提起。落到结构上就是——**间隔越长，加权权重越高**。

强化时的提升量不是固定的，而是随「距上次提起的间隔」增长：

```
gap = now - lastAccessedAt
spacingWeight = 1 + κ · log2( 1 + gap / spacingTau )
newImportance = min( Importance + reinforce · spacingWeight, maxImportance )
```

- `κ`（kappa）控制间隔效应的强度，`spacingTau` 是归一化参考，都在 `settings.json`。
- 于是：昨天刚提过又提一次 → 几乎不加分；隔了一个月再提 → 大幅加分。这正是间隔重复理论（SM-2 / FSRS）的简化版。

此外还有 **检索即复习**：`memory_recall` 命中一条记忆时，顺手更新它的访问计数与时间锚点，轻微强化。

## 7. 巩固（睡眠巩固的类比）

### 问题 5：定期扫描应该如何扫描？扫全局还是仅高价值部分？如何做整理？

之前文档对巩固只有一句话，这里细化。巩固**不是扫全局**，而是**只扫高价值情节记忆**，分三步：

1. **选材（只扫高价值部分）**：从情节记忆里挑出「当前强度 ≥ `strengthThreshold`」或「访问次数 ≥ `minAccessCount`」的条目。低价值、没人碰的记忆不参与，避免把噪音固化。
2. **聚类**：对选出的情节记忆按相似度（`mergeSimilarity`）两两聚类，相似的一族归为一组。
3. **提炼 + 归档**：每组（≥2 条）合并成一条**语义记忆**；原始情节记忆标记为 `archived`（保留但不参与常规检索、权重降低）。

初版第 3 步是**规则式合并**（按访问次数取前几条拼成摘要），并在代码里留了清晰位置，后续可注入 `ctx.llm` 让模型做真正的摘要提炼——这是已明确的迭代方向。

**触发时机**：默认**每 24 小时**执行一次（`consolidation.intervalMs`），而不是每轮。检查点：会话结束时的检查（到点才执行）、启动后 15 秒、每小时一次的定时检查。也可用 `/memory-consolidate` 命令或 `memory_consolidate` 工具立即手动触发。

## 8. 主动复习（开放问题）

除了「睡眠巩固」，还应有一块「主动复习」：找出强度低于阈值、临近期遗忘的记忆，把它们重新带到用户/模型面前。

**尚未定案的是「由谁发起」**，两种模式都已在代码里支持，由 `settings.review.mode` 切换：

- **`manual`（默认）**：由用户用 `/memory-review` 命令主动触发。稳、不打扰，但依赖用户记得去复习。
- **`auto`**：DSH 空闲（`agent/status` 变 `idle`）时，若距上次复习超过 `minIntervalMs`，就把到期记忆通过 `agent.inject` 注入下一次请求的上下文。更「像人」，但可能打扰、且时机不好把握。
- **`off`**：关闭。

这条**先记进备案**，等用起来再根据体验决定默认值。

## 9. 自动自查：每轮对话后自动提取记忆

> 需求：每轮对话后都应该自查有哪些信息应该存入记忆。

当前版本不再依赖用户每次说「记住：」，而是**每轮结束时自动自查**：

1. **缓冲**：监听 `session/event`，把本轮 `user/message`（以及可选的 `assistant/message`）的文本按会话缓冲，并记下事件时间。
2. **过滤**：每轮结束（`agent/turn-stopping`）时，对缓冲文本做启发式判断：
   - 长度 ≥ `autoCapture.minChars`；
   - 不是提问（以「？」或「吗」结尾）、不是问候；
   - 不是注入的提示（以 `【` / `[` 开头或过长）；
   - 含「值得记」的信号词（我叫 / 我的 / 项目 / 偏好 / 要求 / 配置 / 版本 / 决定 / 规则…）。
3. **写入**：命中的文本写入情节记忆，并带上**本轮事件时间**作为 `occurredAt`；内容完全一致时走「再次提起」强化。

每轮最多写 `autoCapture.maxPerTurn` 条，避免刷屏。它是**启发式**而非 LLM 语义判断，可能漏记/误记；可在 `settings.json` 的 `autoCapture` 里调阈值，或关闭自动自查、改用显式 `memory_write`。

**触发时机**：自动自查每轮结束执行（`agent/turn-stopping`）；巩固与工作记忆回收按 24 小时间隔执行，两者不再混在一起。

## 10. 记忆库结构（目录式）与事件日期

### 10.1 目录式记忆库

> 需求：不应该把所有记忆塞在一个文件里，应该建立记忆库。

运行时记忆库按「每条记忆一个文件、按层分目录」组织：

```
~/.dsh/human-memory/
├── index.json                  # 人类可读索引（日期、重要性、内容预览）
└── memories/
    ├── episodic/<id>.json
    ├── semantic/<id>.json
    └── core/<id>.json
```

好处：单条记忆可单独查看/备份/迁移；写入只重写该条文件，不必整库重写；`index.json` 便于人工浏览。加载时扫描 `memories/*/*.json`；旧版单文件 `memories.json` 会在首次加载时自动迁移到目录结构并备份为 `.bak`。

### 10.2 事件日期（回答「这件事是什么时候发生的」）

> 需求：要能回答「这件事是什么时候发生的」。

每条记录除 `createdAt`（写入时间）、`lastAccessedAt`（最后访问）外，新增 **`occurredAt` = 事件真正发生的时间**：

- `memory_write` 可传 `occurredAt`（ISO / `YYYY-MM-DD` / epoch 毫秒），缺省用写入时间；
- 自动自查写入时，用本轮事件的 `event.time` 作为 `occurredAt`；
- 同一事件再次提起时**保留最早的发生时间**；
- `memory_recall` / `/memory-list` / `/memory-review` 的输出都会带上「YYYY-MM-DD HH:mm」。

于是当用户问「这件事是什么时候发生的」，模型可以从召回结果里直接读到日期作答。

### 10.3 行为记忆与时间线（回答「那天那个会话做了什么」）

> 需求：每轮结束后提炼「这一轮做了什么」；同一天同一会话多轮时，能按上下顺序检索到每一轮。

实现：

- 每轮结束（`agent/turn-stopping`）把本轮「用户输入 + 助手回复」摘要写成一条 `kind: 'turn'` 的行为记忆，带 `sessionId`、`turn`、`occurredAt`；
- 行为记忆不参与 `memory_recall` 的事实召回（避免噪音），单独由 `memory_timeline` 检索；
- `memory_timeline({ date?, sessionId?, limit? })` 按时间**正序**返回某天 / 某会话的每一轮。

局限：目前是「用户 + 助手文本」的轻量摘要；要精确到「改了哪些文件、执行了哪些命令」，需进一步接入 `tool/call` / `tool/result` 事件。

### 10.4 设置区卡片（唯一 GUI）

> 需求：只要设置区卡片，像别的插件那样；不要独立的网页 GUI。

- 浏览器半 `client/client.js` 通过 `window.__ModuleLoader__.load({ id, factory(require) })`（lazy-CJS，DSH 自带格式）向 **`settings.section`** 注册设置页分区（做法参考 `dsh-notify-say`）；
- 卡片渲染在 **设置页左侧「记忆」分区**：顶部「打开记忆文件夹」按钮，下方按权重倒序的记忆列表；
- 卡片运行在浏览器半、读不到宿主内存，因此 Host 通过 `ctx.inject(['webServer'])` 在 DSH 内置 Web 服务器上注册只读路由 `/api/dsh-human-memory/memories` 与 `/api/dsh-human-memory/open-folder` 作为数据通道（不额外开端口）；
- 它不是网页 GUI：没有独立页面（`GET /` 返回 404），也没有打开浏览器的命令。

### 10.5 删除缓冲区（trash 文件夹）

- 卡片上的「删除」**不做确认**，立即从列表移除。
- 后端把记录文件**移动到记忆库的 `trash/` 文件夹**（文件夹名由 `storage.trashDir` 配置，默认 `trash`），不再出现在当前记忆区、召回、复习、巩固中；文件保留，方便备份/恢复。
- 下一次巩固时统一物理删除（`trash/` 下的文件被移除）；也可通过 `POST /restore` 恢复。

## 11. 配置文件（settings.json）

所有可调参数集中在一个 `settings.json`（JSONC，支持 `//` 注释），**每个字段都有中文注释说明作用**，用户直接改文件即可，无需改代码。包含：

- 存储路径与落盘策略
- 自动自查开关与阈值（`autoCapture`）
- 遗忘曲线参数（`tauMs`、`c`、幂律开关与 `β`）
- 六维重要性权重
- 检索三项权重（`α/β/γ`）
- 间隔效应参数（`κ`、`reinforce`）
- 巩固阈值、归档策略与**触发间隔** `intervalMs`
- 主动复习模式与阈值
- 工作记忆：`capacity`（0=不限）、`minRetentionMs`（最小保留时间）、`importance`（权重）、`enabled`

配置加载失败或字段缺失时自动回退默认值并告警，不会让插件崩溃。

## 13. 已知限制与迭代方向

- **自动自查是启发式**（关键词 + 长度 + 过滤），不是 LLM 语义判断，可能漏记/误记 → 可接入 `ctx.llm` 做语义抽取。
- **行为记忆是「用户 + 助手 + 工具名」摘要**（已接入 `tool/call` 的工具名与文件/命令），但尚未记录参数 diff。
- **工作记忆**已落地为 `memories/working/`（低权重、短寿命、自动清理），但只记录文件/命令级操作。
- **对话习惯 / 用户画像**：见 [迭代方向-用户画像记忆.md](./迭代方向-用户画像记忆.md)，**未来方向，暂未实现**。
- **语义相关度**目前是 n-gram 相似度，长文本/跨表述语义匹配不准 → 接入 embedding。
- **巩固提炼**目前是规则式拼接 → 接入 `ctx.llm` 做摘要。
- **自动复习的发起者**（DSH 主动 vs 用户命令）尚未定案。
- **多实例并发**写同一记忆库无文件锁，后写覆盖（单实例内无碍）。
- **设置区卡片**注册在 `settings.section`（设置页左侧「记忆」分区），数据走 DSH 内置 Web 服务器的 `/api/dsh-human-memory` 路由。
- **市场分发**：目前本地 `link:` 安装，需发布 npm/git 并加 `dsh-plugin` topic 才能被市场扫描。

## 14. 总结

赋予 DSH 遗忘曲线的关键，是用**多因子加权的检索分数**模拟记忆可访问性：

- **分层架构 + 目录式记忆库**管理生命周期与持久化；
- **重要性评分（含记忆时长）**体现内容因素；
- **时间衰减（惰性计算，无需每日更新）**体现遗忘曲线；
- **间隔重复 + 间隔效应（间隔越长加权越高）**让记忆越用越牢；
- **每轮自动自查**让记忆在对话中自然沉淀；
- **巩固（只扫高价值部分）与主动复习**分别对应睡眠巩固与提取练习；
- **`occurredAt`** 让「这件事是什么时候发生的」可被回答。

三者共同决定一条记忆检索时的排名。所有权重与参数都收在 `settings.json`，用户可调。当前只是第一版，期待大佬迭代。
