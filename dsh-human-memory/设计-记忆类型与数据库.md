# 设计：记忆类型化与数据库索引（0.1.3）

> 本文记录 0.1.3 的两块设计：**三轴记忆类型化** 与 **node:sqlite 索引**。代码已实现，测试见 [测试文档.md](./测试文档.md)。

## 一、三轴记忆类型化

人类对不同类型记忆的回忆方式不同：工作记忆只记得「那天做了什么」，细节要重新接触才想起；情绪记忆突出情绪核心、淡化周边。对应到设计上是三条轴。

### 轴 A：粒度（gist / detail）

每条记忆带一个 `fidelity` 字段：

- `gist`（默认）：梗概，默认可见、抗遗忘；
- `detail`：细节，默认不返回，需要 `detail` 查询或线索才带出。

**为什么需要**：数据库能按条件查到一切，但「能查到」不等于「应默认返回」。默认只给梗概，避免问「昨天做了什么」时把文件、命令、参数全倒出来。

**线索从哪来**：不单独维护 `cues` 索引——数据库的 `session_id`、`occurred_at`、`layer` 就是线索。轴 A 只负责「默认只给梗概、细节要下钻」。

**接口**：

- `memory_recall({ query, detail?: boolean })`
- `memory_timeline({ date?, sessionId?, detail?: boolean })`

### 轴 B：情绪识别

不只匹配「开心/生气」，而是多信号加权：

| 信号 | 例子 | 权重 |
|------|------|------|
| 显式情绪词 | 开心、生气、难过、害怕、讨厌、惊喜、沮丧 | 0.5 |
| 抱怨/重复模式 | 又…这样 / 又…错 / 又…搞 | 0.4 |
| 语气词 / 感叹词 | 哇、哦、啊、唉、哎、呀、哈、嗯、哼、咦、呜、靠、卧槽、天哪、绝了、离谱、服了、无语、麻了、破防、上头、下头、笑死、哭死 | 0.3 |
| 强调副词 | 太、真、特别、非常、超级、巨、简直、完全、根本、竟然、居然、怎么 | 0.2 |
| 反问/反讽 | 不是吧、这也行、行吧、随便、呵呵、就这 | 0.2 |
| emoji | 😄😡😭😱 | 0.2 |
| 重复/拖长 | 好好好、哈哈哈、啊啊啊 | 0.15 |
| 标点 | `!`/`！`（封顶 0.3）、`……`/`...`（0.2）、`?`/`？`（0.1）、`~`/`～`（0.1） | 0.1–0.3 |

```
intensity = 1 - exp(-sum(weights))      // 0..1，饱和
kind      = 权重最高的非 neutral 信号
core      = 包含最强信号的子句
```

强度 ≥ `settings.emotion.threshold`（默认 0.2）才记为「情绪记忆」。

### 轴 C：一条记录 + 多个面（facets）

一句「哇你又犯错了」同时含情绪、事件、操作细节。**不要拆成三条记录**（会重复、衰减不一致），而是一条事件记录带多个字段：

```jsonc
{
  "layer": "episodic",
  "kind": "event",
  "content": "用户指出我又犯了同类错误",      // gist
  "fidelity": "gist",
  "details": ["涉及文件：…", "命令：…"],       // 细节 facet
  "emotionKind": "frustration",
  "emotionIntensity": 0.55,
  "emotionCore": "哇…又…",
  "sessionId": "…",
  "tags": ["error", "recurring"]
}
```

- **层级**：先看事件性质 → `episodic`；情绪是 facet，不单独占层。
- **细节**：具体文件/命令放 `details`（或关联的 `working` 记录，`fidelity: "detail"`），只在细节模式带出。
- **重复发生**：`reinforce`，`emotionIntensity` 取较大值；反复出现可提升为 `core`。

## 二、数据库索引（node:sqlite）

### 原则

- **文件仍是唯一真源**：`memories/<layer>/<id>.json`、`trash/`、`state.json` 不变。
- **数据库只是可重建索引**：`<root>/.index/memory.sqlite`，删掉也能从文件重建。
- **零额外构建**：用 Node 内置 `node:sqlite`（DSH 运行时 Electron 44.7.0 / Node 24.21.0 已验证可用），不引入原生模块。

### Schema

```sql
CREATE TABLE memories (
  id TEXT PRIMARY KEY,
  path TEXT NOT NULL,          -- 相对路径，如 memories/episodic/xxx.json
  layer TEXT NOT NULL,
  kind TEXT,
  fidelity TEXT,               -- gist | detail
  session_id TEXT,
  occurred_at INTEGER NOT NULL,
  importance REAL,
  emotion_kind TEXT,
  emotion_intensity REAL,
  gist TEXT,
  details_json TEXT,
  deleted_at INTEGER,
  mtime INTEGER, size INTEGER
);
CREATE INDEX idx_time         ON memories(occurred_at);
CREATE INDEX idx_session_time ON memories(session_id, occurred_at);
CREATE INDEX idx_emotion      ON memories(emotion_kind, occurred_at);
CREATE INDEX idx_layer_time   ON memories(layer, occurred_at);
CREATE INDEX idx_fidelity     ON memories(fidelity, occurred_at);
```

### 同步与重扫

- 启动：`MemoryLibrary` 加载文件后 `index.rebuild(...)`。
- 写入/删除/移入 trash：同步更新索引。
- **外部变动**：用户对 DSH 说「重新扫描记忆」，DSH 调用 `memory_rescan` 工具（先 `flush` 落盘，再重扫文件、重建索引）。不做文件监听。
- **回退**：`node:sqlite` 不可用时，索引方法安静降级为空结果，插件仍靠文件工作。

### 快速查询

- 某天：`SELECT … WHERE occurred_at >= ? AND occurred_at < ? AND fidelity = 'gist' ORDER BY occurred_at`
- 某会话：`SELECT … WHERE session_id = ? AND fidelity = 'gist' ORDER BY occurred_at`
- 细节：同上，`fidelity = 'detail'`

### 目录结构演进

- 索引器扫描记忆库根目录下的 `*.json`（排除 `.index/`、`trash/`、`state.json`、`memories.json*`）。
- `layer` 优先取记录字段，缺省取路径首段；`path` 存相对路径。
- 以后新增目录（如 `portrait/`）无需改 schema，重扫即可。

## 三、字段与模块映射

| 能力 | 字段 / 模块 |
|------|-------------|
| 粒度 | `fidelity`（memory.js） |
| 情绪 | `emotionKind` / `emotionIntensity` / `emotionCore`（emotion.js + memory.js） |
| 细节 | `details: string[]`（memory.js） |
| 索引 | `src/index-db.js`（node:sqlite） |
| 重扫 | `memory_rescan` 工具 / `/memory-rescan` 命令 |
