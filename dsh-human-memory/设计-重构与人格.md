# 设计：重构底座与人格串联（0.1.4）

> 本版只做两件事：**让回忆变成“重构”**，以及**让人格参数参与重构**。
> 不新增记忆层、不新增存储、不碰多 Agent / 工作台。

## 一、为什么不是加一个“项目记忆”

本项目采用的记忆模型是：

- **分布式**：一个事件散在多个脑区，不同线索唤起不同侧面；
- **重构式**：回忆是按线索重新生成一个版本，不是取回一条记录；
- **预测**：用过去经验生成对当前情境的解释与行动预案；
- **人格是参数网**：注意、解释、提取、行动、表达。

所以“下次从哪开始”不该是一个新的 `project` 表，而是**对已有会话/时间/顺序记录的重构**。本版只给记录加“表达字段”，让重构有素材可用。

## 二、存储表达（字段，不是新结构）

| 字段 | 作用 |
|------|------|
| `eventId` | 把一个事件的分布式记忆串起来（情景/语义/情绪/程序/自传体共用） |
| `cues` | 线索：`{ person, place, topic, time, emotion }`，不同线索唤起不同侧面 |
| `source` | `user / assistant / tool / inference / self`，事实与推断分开 |
| `confidence` | 0~1，推断 < 1 |
| `status` | `active / candidate / superseded` |
| `validFrom` / `validTo` | 该判断的有效区间 |
| `lastConfirmedAt` | 最近一次得到确认的时间 |
| `reconsolidationCount` / `lastReconstructedAt` | 被重构过的次数与时间（原文不改） |
| `layer` | 扩展 `procedural`（技能）、`autobiographical`（自传体）——同一套记录结构 |

旧记录缺这些字段时按默认值读取，不迁移、不改目录。

## 三、重构（`memory_reconstruct`）

### 取材

按当前线索，对全部记录打分：

```
score = (相关度 + 线索重合) * 检索权重
      + 强度 * 权重
      + 重要性 * 权重
```

再乘上人格的「提取偏向」（`persona.retrieval[脑区]`），过滤 `superseded`、`archived`、`deletedAt`。

### 分区

把命中的记录按 `layer` 归入：情景 / 语义 / 情绪 / 程序 / 自传体 / 工作记忆。情绪分区额外收纳任何 `emotionIntensity ≥ threshold` 的记录。

### 组合

```
我记得：<情景 gist>
那时的感觉：<情绪核心>（<类型> <强度>）
这让我想到：<语义概念>
类似地，我会：<程序技能>
一路走来：<自传体>
细节：<details>（可选）
```

这就是“按当前线索重新生成一个版本”，不是把原文拼起来。

### 缺口与置信度

- `gaps`：哪些分区没有素材（例如只有情景、没有语义）；
- `confidence`：按命中数量与平均强度估算；
- `sources`：本次引用到的记录 id。

### 再巩固

被重构引用的记录：

- `reconsolidationCount += 1`
- `lastReconstructedAt = now`
- `lastAccessedAt = now`

**原文内容不动**。如果模型要写“重构后的版本”，用普通 `memory_write` 写一条新记录，用 `eventId` 挂到同一事件上。

## 四、续接（`memory_resume`）

不存项目表：

1. 取该会话 `kind = turn` 的记录，按 `turn` / `occurredAt` 排序；
2. 取最近 N 轮；
3. 组合成 `goal`（第一轮）、`done`（中间轮）、`last`（最后一轮）、`next`（从最后一条的 details 里找“下一步/待办”，找不到就留空由模型推断）；
4. 用最后一轮的内容做一次重构，附上 `related`。

## 五、预测（`memory_predict`）

对当前情境做一次重构，按用途拆开：

| 字段 | 来源 | 回答 |
|------|------|------|
| `what` | 语义 | 这是什么情况 |
| `before` | 情景 | 类似情况以前怎样 |
| `how` | 程序 | 这样做会怎样 |
| `risk` | 情绪 | 这危险/重要 |
| `prediction` | 组合文本 | 综合预案 |

## 六、人格串联

人格不是记忆结构，是一组参数（`src/persona.js`）：

```jsonc
{
  "attention":   { "person": 1, "place": 1, "topic": 1, "time": 1, "emotion": 1 },
  "retrieval":   { "working": 0.6, "episodic": 1, "semantic": 1, "emotional": 1, "procedural": 1, "autobiographical": 1 },
  "interpretation": { "logic": 0.5, "warmth": 0.5, "caution": 0.5 },
  "expression":  { "directness": 0.5, "verbosity": 0.5 }
}
```

- **注意**：`attention` 影响线索重合的权重（先注意“人”还是“地点/主题/时间/情绪”）；
- **提取**：`retrieval` 影响哪个脑区更容易被想起；
- **解释/表达**：交给模型的框架提示（记忆侧只给素材，不替模型判断）。

### 反馈 → 参数

- `memory_feedback` 写一条普通记忆：`kind: 'feedback'`、`layer: 'autobiographical'`、`trait`、`direction`；
- `memory_persona` 读取反馈，用 `suggestPersonaDeltas` 给出增量建议（不自动改）；
- `memory_persona_update` 把某个参数写入 `persona.json`，下次启动生效。

这就是“人格自我迭代”的记忆侧闭环：**经历 → 反馈记忆 → 参数调整 → 下次回忆的偏向改变**。

## 七、边界

- 不新增记忆层/存储：`layer` 只是多了 `procedural` / `autobiographical` 两个取值；
- 不存“项目状态”：续接是读时重构；
- 不做多 Agent / 工作台；
- 人格只做记忆侧能承接的注意/提取/解释/表达，不替代上层决策；
- `memory_predict` 是只读组合，不训练、不调用模型。
