## 4. 手动测试用例（验收清单）

> 表格中「实测」列：✅ 已完成；⬜ 待执行。执行时把结果补到「实测」。

### A. 加载与注册

| 编号 | 步骤 | 预期 | 实测 |
|------|------|------|------|
| A1 | 重启 DSH，观察启动日志 | 无 `did not activate human-memory` 告警 | ✅ |
| A2 | 问 agent「列出你的 memory 工具」 | 出现 5 个：write / recall / forget / consolidate / review | ✅ |
| A3 | 输入 `/` 观察命令补全 | 出现 `memory-list` / `memory-review` / `memory-consolidate` | ⬜ |
| A4 | 首次 `memory_write` 后看磁盘 | 生成 `~/.dsh/human-memory/index.json` 与 `memories/<layer>/<id>.json` | ✅ |

### B. 写入（memory_write）

| 编号 | 步骤 | 预期 | 实测 |
|------|------|------|------|
| B1 | 说「记住：这个项目用 Python 和 Vue 开发」 | 调用 `memory_write`，返回「已记住 …（重要性 0.xx）」 | ✅ |
| B2 | 再次说同一句话（内容完全一致） | 不新增记录，`mentionCount` +1、`importance` 上调 | ⬜ |
| B3 | 说「把这条存为语义记忆：…」并指定 layer | 记录 `layer: "semantic"` | ✅（现有一条 semantic） |
| B4 | 同一内容分别带 `dwellMs: 1000` 与 `600000` 写入 | 后者重要性更高（记忆时长维度生效） | ⬜ |

### C. 召回（memory_recall）

| 编号 | 步骤 | 预期 | 实测 |

## 5. 边界与异常

| 编号 | 场景 | 预期 |
|------|------|------|
| X1 | 空字符串内容 | 正常写入（或按需拒绝），不崩溃 |
| X2 | 超长内容（数千字） | 正常写入，`importance.uniqueness` 饱和 |
| X3 | 含换行 / 引号 / emoji 的内容 | 正常存储与召回（JSON 转义正确） |
| X4 | 数据文件被占用或损坏 | 插件告警并从空记忆开始，不崩溃 |
| X5 | 并发写入（多会话同时写） | 单线程 event loop 串行，不丢记录 |
| X6 | 会话中途 DSH 被强杀 | 未落盘的最近 5 秒改动可能丢失（已知限制） |

1. `test/self-test.mjs` 与 `test/plugin-smoke.mjs` 全部通过。
2. 用例 A/B/C/D/F/J/L/M 全部 ✅（G/E 为增强功能，可接受但应可执行）。
3. 无未捕获异常；`settings.json` 非法时能回退。
4. 记忆库位置符合预期，内容为合法 UTF-8 JSON。

## 7. 已知限制（不覆盖项）

- **自动自查是启发式**：用关键词 + 长度 + 提问/问候过滤，不是 LLM 语义判断，可能漏记或误记；可用 `autoCapture` 调阈值或关闭。
- **语义相关度**用字符 n-gram，未接 embedding，长文本/同义改写匹配不够准。
- **巩固**是规则式拼接，未接 LLM 摘要。
- **批量落盘**默认 5 秒，强杀会丢最近改动；需要立即持久化可把 `storage.syncWrite` 设为 `true`。
- **跨安装不共享**：记忆绑定 `DSH_HOME`；不同 profile/安装若 `DSH_HOME` 不同则各自独立。
