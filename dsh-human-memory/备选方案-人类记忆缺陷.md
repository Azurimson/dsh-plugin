# 人类记忆缺陷 · 备选实现方案

## 0. 为什么要单独写这份文档

人类的记忆系统远非完美，甚至可以说「bug 一堆」。当我们给 DSH 造一套「人类式记忆」时，会遇到一个选择：**哪些人类记忆的特征值得模仿，哪些其实是缺陷、不该照搬？**

有些「缺陷」其实是特征——例如「遗忘」是为了让系统聚焦重要信息，值得实现；「干扰」能逼我们做去重与对比，也值得实现。但另一些（如虚假记忆、记忆篡改）是可靠性事故，**刻意实现反而有害**。

本文逐条列出人类记忆的典型缺陷，给出**能否实现、如何实现、是否建议做**三项判断，作为主方案 [实现思路.md](./实现思路.md) 之外的备选参考。

## 1. 判断原则（先定标准）

对每一条缺陷，用三个问题打分：

1. **它能否让 DSH 更「像人」、更可用？** 能 → 加分。
2. **它是否会损害答案的可靠性 / 可复现性？** 会 → 减分。
3. **实现成本是否可控？** 可控 → 加分。

结论倾向：

- **值得模仿**：遗忘、干扰（及其应对）、提取失败、序列位置效应、工作记忆容量限制、情绪对细节的损耗——这些既像人，又能逼系统做「去重/对比/优先级」，整体有益。
- **不应模仿**：虚假记忆、易受暗示、记忆篡改——这些是纯事故，故意实现只会降低可靠性。

## 2. 逐条分析

### 2.1 相似的记忆互相干扰（前摄抑制 / 倒摄抑制）

**现象**：学 A 后再学 B，B 会干扰对 A 的回忆（倒摄抑制）；先前学的 A 干扰后来学的 B（前摄抑制）。典型场景：连续背一组相似单词、看十个相似病例，细节全混。

**能否实现**：能，且**初版已部分覆盖**。相似项密集会天然压低检索区分度（因为 n-gram 相似度都高），使它们互相「抢排名」。

**如何实现（补强）**：
- 写入时检测「同批相似项」：若新记忆与已有记忆相似度 ≥ 阈值，给两条都打上「易混淆」标记。
- 对易混淆组，检索时同时返回对比信息（如「这条与 X、Y 相似，区别是…」），而非只返回得分最高的一条。
- 可选：对相似项做「对比表」式合并（主方案里巩固的聚类已复用这一逻辑）。

**建议**：**做**。它是「主动去重」的天然驱动力，能显著减少记忆库冗余。

### 2.2 记得某件事但想不起来（舌尖现象 / 提取失败）

**现象**：信息还在脑里，但缺少线索提取不出来——「我明明记得见过这概念，就是想不起名字」。

**能否实现**：能。这正是主方案「遗忘 = 降低可访问性而非删除」的直接体现：记忆没删，只是检索分低到「够不着」。

**如何实现**：
- 保证「遗忘」只降检索排名、**永不物理删除**（除非用户显式 `memory_forget`），于是「想不起来」成了可逆状态。
- 提供「多线索」：检索不只看语义相似，还按 `layer`、标签、时间窗口等辅助线索兜底（如 `/memory-list` 可全量浏览）。
- 可选：`memory_recall` 支持「模糊回忆」——把得分略低于阈值的记忆也作为「弱候选」返回，模拟「话到嘴边」。

**建议**：**做**（核心机制已在初版）。

### 2.3 遗忘（痕迹衰退）

**现象**：不复习，记忆逐渐弱化，先快后慢。

**能否实现**：能，主方案核心。用惰性时间衰减 `exp(-(age/τ)^c)` 实现，**无需每日更新**。

**建议**：**已做**，见主方案第 2、4 节。

### 2.4 首因效应 / 近因效应（序列位置效应）

**现象**：列表的开头和结尾比中间更容易被记住。

**能否实现**：能，且简单。

**如何实现**：
- 检索排序时给「最近写入 / 最近访问」的记忆加一点近因加成（recently 优先），给「最早建立的核心记忆」加首因加成。
- 作用已部分隐含在时间衰减里（越新越强）；若要显式模拟，可在 `retrieval` 里再加一个 `recency` 权重项。

**建议**：**可选**。近因部分已被时间衰减覆盖；首因可作为「核心记忆抗遗忘」的补充。

### 2.5 闪光灯记忆不准确（高情绪下的细节损耗）

**现象**：强烈情绪事件的核心记得牢，但周边细节、顺序、数字反而受损——「只记得出事了，记不清细节」。

**能否实现**：能，且值得做。

**如何实现**：
- 重要性评分里，情绪分 `emotion` 只抬升「核心内容」的整体权重，但不提高（甚至降低）对细节字段的精确度信心。
- 可给每条记忆加一个「细节置信度」字段：高情绪时核心置信度高、细节置信度低；检索结果据此标注「核心可靠、细节存疑」。

**建议**：**可选**（偏学术，收益中等）。

### 2.6 虚假记忆 / 记忆重构

**现象**：人会「记得」从未发生过的事，或在回忆时把记忆按当前信念重新拼装、添油加醋。

**能否实现**：技术上能（让 LLM 在巩固时「脑补」细节），但**不应做**。

**如何实现（仅说明，不推荐）**：巩固时让 LLM 自由发挥补全叙事 → 产生「合理的错误」。

**建议**：**不做**。会损害可靠性。相反，应在巩固时**显式保留来源**（哪些语义记忆来自哪几条情节记忆），并保留「原文」而非脑补，把重构降到最低。

### 2.7 易受暗示（suggestibility）

**现象**：问题怎么问，回忆就怎么偏——诱导性提问会让人「记起」不存在的细节。

**能否实现**：技术上能，但**不应做**。

**建议**：**不做**。对应到系统上，检索应尽量**与查询措辞解耦**（用规范化、去偏见的相似度），而不是让查询诱导记忆内容。

### 2.8 工作记忆容量限制（7±2 组块）

**现象**：人一次只能在工作记忆里保持约 7±2 个组块，超出就丢。

**能否实现**：能。DSH 本身就有上下文窗口限制，这是天然的类比。

**如何实现**：
- 定义「工作记忆」= 当前会话最近 N 条（`workingMemory.capacity`，默认 7）的关键信息。
- 超出容量时，重要内容「溢写」到情节记忆，其余丢弃——这对应主方案分层架构里工作记忆的溢出动作。

**建议**：**做**，但初版只做了概念与配置项，尚未自动从会话抓取，列为迭代项。

### 2.9 状态依赖记忆（情绪/情境依赖）

**现象**：在什么状态下学的，就在什么状态下更容易想起来。

**能否实现**：能，成本略高。

**如何实现**：记录写入时的情境标签（主题、时间、对话角色），检索时若当前情境匹配则加权。

**建议**：**可选 / 暂缓**，收益不确定，先不做。

### 2.10 记忆的自我中心偏差

**现象**：与自己相关的信息被过度看重、记得更牢。

**能否实现**：能，且已在主方案。

**如何实现**：重要性评分里 `selfRelevance` 权重最高（默认 0.25），正是对这一偏差的「主动建模」。

**建议**：**已做**（作为内容因素的一维）。

## 3. 汇总

| 缺陷 | 能否实现 | 是否建议 | 初版状态 |
|------|:---:|:---:|:---:|
| 相似记忆互相干扰 | ✅ | ✅ 做 | 部分（相似度天然互抢，补强待做） |
| 记得但想不起来（提取失败） | ✅ | ✅ 做 | 已做（遗忘=降排名不删除） |
| 遗忘（痕迹衰退） | ✅ | ✅ 做 | 已做（惰性时间衰减） |
| 首因/近因效应 | ✅ | 🔶 可选 | 近因被时间衰减覆盖 |
| 闪光灯记忆细节损耗 | ✅ | 🔶 可选 | 未做 |
| 虚假记忆/记忆重构 | ✅ | ❌ 不做 | 反向：巩固保留来源 |
| 易受暗示 | ✅ | ❌ 不做 | 反向：检索与措辞解耦 |
| 工作记忆容量限制 | ✅ | ✅ 做 | 概念+配置，自动抓取待做 |
| 状态依赖记忆 | ✅ | 🔶 暂缓 | 未做 |
| 自我中心偏差 | ✅ | ✅ 做 | 已做（selfRelevance 权重） |

## 4. 结论

- **主动实现的缺陷**（让系统更像人、更聚焦）：遗忘、提取失败、相似干扰及其应对、工作记忆容量、自我中心偏差——这些已基本落在初版里。
- **主动规避的缺陷**（纯事故）：虚假记忆、易受暗示——实现它们只会降低可靠性，应反其道而行（保留来源、检索去偏）。
- **待定**：首因/近因、闪光灯细节、状态依赖，收益不确定，留作备选，等有真实使用反馈再决定。

一句话：**我们模仿的是「人类记忆如何在有限资源里取舍」，而不是「人类记忆如何出错」。**
