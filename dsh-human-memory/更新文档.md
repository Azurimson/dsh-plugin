# 更新文档（Changelog）

## v0.1.1 — 2026-10-29

本版针对三条反馈做了改造：**每轮自动自查**、**目录式记忆库**、**事件日期**，并附带**旧版自动迁移**。

| # | 变化 | 涉及文件 |
|---|------|----------|
| 1 | 每轮对话后自动自查并写入记忆（不必每次说「记住：」） | `src/index.js`、`settings.json` |
| 2 | 记忆库从单文件改为目录式（每条记忆独立成文件） | `src/store.js` |
| 3 | 每条记忆记录「事件发生时间」，召回时一并展示 | `src/memory.js`、`src/index.js` |
| 4 | 旧版 `memories.json` 自动迁移到新结构 | `src/store.js` |

### 1. 每轮对话后自动自查

**变化**

- 插件监听 `session/event`，把本轮 `user/message`（可选 `assistant/message`）按会话缓冲；
- 在 `agent/turn-stopping`（每轮结束）时做启发式判断：
  - 长度 ≥ `autoCapture.minChars`（默认 8）；
  - 不是提问（`？` / `吗` 结尾）、不是问候；
  - 不是注入提示（`【` / `[` 开头或过长）；
  - 含「值得记」的信号词（我叫 / 我的 / 项目 / 偏好 / 要求 / 配置 / 版本 / 决定 / 规则…）。
- 命中则写入情节记忆，内容完全一致时走「再次提起」强化；每轮最多 `maxPerTurn` 条。
- 默认开启，可在 `settings.json` 关闭或调阈值。

**如何测试**

1. **正例**：新开一轮，直接说一句含偏好的话（**不要说「记住」**）：
   > 我的项目用 Rust 写后端，部署在本地服务器上。
   - 等本轮结束；
   - 打开 `C:\Users\<你>\.dsh\human-memory\memories\episodic\`，应新增一个 `.json`；
   - 或问「我刚才说了什么？」，应调用 `memory_recall` 并答出上述内容。
2. **反例**：只发一句提问：
   > 这个项目的数据库用的是什么？
   - 预期：**不**新增记忆（提问不是事实）。
3. **重复**：把同一句话再说一遍：
   - 预期：不新增记录，`mentionCount` +1、`importance` 上调（间隔效应）。
4. **关闭**：把 `settings.json` 的 `autoCapture.enabled` 改为 `false`，重启 DSH：
   - 预期：不再自动写入，只能靠显式 `memory_write`。

**预期结果**

| 场景 | 预期 |
|------|------|
| 含偏好的陈述 | 自动写入一条 episodic 记忆 |
| 纯提问 / 问候 | 不写入 |
| 同一句重复 | 强化原记录，不新增 |
| 关闭开关 | 不自动写入 |

**可调参数**

| 参数 | 作用 | 默认 |
|------|------|------|
| `autoCapture.enabled` | 是否开启每轮自动自查 | `true` |
| `autoCapture.minChars` | 短于该长度不写入 | `8` |
| `autoCapture.maxPerTurn` | 每轮最多写几条 | `3` |
| `autoCapture.includeAssistant` | 是否也自查 assistant 回复 | `false` |

### 2. 目录式记忆库

**变化**

存储从「单个 `memories.json`」改为「每条记忆一个文件、按层分目录」：

```
C:\Users\<你>\.dsh\human-memory\
├── index.json                  # 索引：日期、重要性、内容预览、文件路径
└── memories\
    ├── episodic\<id>.json      # 情节记忆
    ├── semantic\<id>.json      # 语义记忆
    └── core\<id>.json          # 核心记忆
```

- 写入只重写该条对应的文件，不再整库重写；
- `index.json` 便于人工浏览（含 `occurredAt`、`importance`、`preview`、`file`）；
- 单条记忆可单独查看 / 备份 / 迁移。

**如何测试**

1. 触发一次写入（自动或手动均可）。
2. 打开 `C:\Users\<你>\.dsh\human-memory\`，确认：
   - `index.json` 存在，`count` 与 `memories.length` 一致；
   - `memories\episodic\`（或对应层）下出现 `<id>.json`。
3. 打开某个 `<id>.json`，确认字段包含
   `id / content / layer / createdAt / occurredAt / lastAccessedAt / accessCount / mentionCount / importance / factors / dwellMs / archived`。
4. 删除一条记忆，等 ≥ 5 秒（批量落盘间隔），确认对应文件消失、`index.json` 的 `count` 减一。

**预期结果**

- 目录与文件按层生成；
- `index.json` 与记忆文件一致；
- 删除后文件被移除。

### 3. 事件日期（`occurredAt`）

**变化**

新增 `occurredAt` = **事件真正发生的时间**，与 `createdAt`（写入时间）、`lastAccessedAt`（最后访问）区分：

- `memory_write` 支持传 `occurredAt`（`YYYY-MM-DD`、ISO 字符串、或 epoch 毫秒）；
- 自动自查写入时，用**本轮事件时间**作为 `occurredAt`；
- 同一事件再次提起时，**保留最早的发生时间**；
- `memory_recall` / `/memory-list` / `/memory-review` 输出都带 `[YYYY-MM-DD HH:mm]`。

**如何测试**

1. **自然语言**：说
   > 记住：2026-01-15 的会上我们决定用 PostgreSQL。
   - 查看 `memories\episodic\<id>.json`，`occurredAt` 应对应 2026-01-15（若模型未传日期，则回退为写入时间——此时改用第 2 种方式验证）。
2. **直接参数**（最可靠）：通过工具调用 `memory_write`，显式传 `occurredAt: "2026-01-15"`；
   - 预期：记录里的 `occurredAt` = 2026-01-15 00:00（本地时区）。
3. **问答**：问「我们什么时候决定用 PostgreSQL 的？」
   - 预期：`memory_recall` 返回的结果带 `[2026-01-15 ...]`，模型据此作答。
4. **重复提及**：隔一段时间再次写入同一事件；
   - 预期：`occurredAt` 仍是最早时间，不会改到更晚。

**预期结果**

| 场景 | 预期 |
|------|------|
| 指定日期写入 | `occurredAt` 为该日期 |
| 自动自查写入 | `occurredAt` 为本轮事件时间 |
| 重复提及 | 保留最早 `occurredAt` |
| 问答「什么时候」 | 召回输出含日期，可作答 |

### 4. 旧版单文件自动迁移

**变化**

插件启动时若发现 `human-memory/memories.json`：

- 把其中每条记录拆分到 `memories/<layer>/<id>.json`；
- 旧记录补 `occurredAt = createdAt`；
- 原文件重命名为 `memories.json.bak`（保留备份，不删除）。

**如何测试**

1. 升级前先看 `memories.json` 里有几条记录（本机升级前为 3 条）。
2. 重启 DSH。
3. 检查目录：
   - `memories.json` 已不存在，出现 `memories.json.bak`；
   - `memories\<layer>\` 下有对应数量的 `.json`；
   - `index.json` 的 `count` 等于原条数；
   - 旧记录的 `occurredAt` 已补齐（等于其 `createdAt`）。

**预期结果**

- 数据无损迁移；
- 原文件保留为 `.bak`；
- 迁移后召回结果与迁移前一致。

### 升级步骤（0.1.0 → 0.1.1）

1. 代码已更新到本目录（`package.json` 版本 `0.1.1`）。
2. **重启 DSH**（插件在启动时加载，改动后必须重启）。
3. 首次启动会自动把旧 `memories.json` 迁移为目录结构。

## v0.1.0 — 初始版本

首个可用版本，包含：

- **5 个工具**：`memory_write` / `memory_recall` / `memory_forget` / `memory_consolidate` / `memory_review`
- **3 个斜杠命令**：`/memory-review` / `/memory-consolidate` / `/memory-list`
- **遗忘曲线**：惰性时间衰减，无需每日更新
- **六维重要性**：自我相关、因果、具体、独特、情绪、记忆时长
- **间隔重复 + 间隔效应**：间隔越久再次提起加权越高
- **巩固与复习**：高价值情节记忆合并为语义记忆；临期记忆进入复习
- **集中配置**：所有权重与参数在 `settings.json`（中文注释）
- **本地存储**：单文件 `memories.json`

初始版本测试：`test/self-test.mjs`（11 项）、`test/plugin-smoke.mjs`（8 项）。
