## v0.1.4 — 2026-10-31

本版是**重构底座 + 人格串联**的初版：不新增记忆层/存储，只给现有记录加“表达字段”，并加上读时重构与人格参数网。详见 [设计-重构与人格.md](./设计-重构与人格.md)。

| # | 变化 | 涉及文件 |
|---|------|----------|
| 1 | 记录新增 `eventId` / `cues` / `source` / `confidence` / `status` / `validFrom` / `validTo` / `reconsolidationCount` | `src/memory.js` |
| 2 | `layer` 扩展 `procedural` / `autobiographical`（同一结构） | `src/memory.js` |
| 3 | 重构：按线索组合情景/语义/情绪/程序/自传体，返回缺口与来源 | `src/memory.js` |
| 4 | 续接：`memory_resume` 把会话顺序记录拼成目标/做到/最后/下一步 | `src/memory.js` |
| 5 | 预测：`memory_predict` 返回概念/案例/后果/风险 | `src/memory.js` |
| 6 | 人格参数网：注意/提取/解释/表达权重，影响重构取材 | `src/persona.js` |
| 7 | 反馈记忆 → 人格参数建议；`memory_persona_update` 持久化 | `src/index.js`、`persona.json` |
| 8 | SQLite 索引补列（event_id / source / status / confidence / cues_json） | `src/index-db.js` |
| 9 | `memory_doctor`：健康检查（记录/索引/回收站/损坏文件/候选/反馈） | `src/index.js` |

### 1. 存储表达（不新增结构）

- 同一事件的多条记忆用 `eventId` 串起来（分布式）；`cues` 让不同线索唤起不同侧面。
- `source` 区分事实/推断；`status` 支持 `active / candidate / superseded`；`validFrom/To` 表示有效区间。
- 全部是可选字段，旧记录缺省即默认值，不迁移、不改目录。

### 2. 重构（`memory_reconstruct`）

- 按线索从多个分区取材，组合成「我记得 / 那时的感觉 / 这让我想到 / 类似地我会 / 一路走来」。
- 返回 `gaps`（缺哪些分区）与 `confidence`；引用到的记录 `reconsolidationCount++`，原文不改。
- 支持 `asOf` 查某个时间点的版本。

### 3. 续接（`memory_resume`）

- 不存项目表：取该会话 `kind=turn` 的记录，按 `turn` 排序，重构成目标/做到/最后/下一步。

### 4. 预测（`memory_predict`）

- 语义给概念、情景给案例、程序给后果、情绪给风险；只读组合。

### 5. 人格串联

- `persona.attention` / `persona.retrieval` 影响重构取材；
- `interpretation` / `expression` 作为给模型的框架提示；
- `memory_feedback` 写普通反馈记忆，`memory_persona` 给出增量建议，`memory_persona_update` 写入 `persona.json`。

### 6. 健壮性与诊断

- **损坏容错**：损坏的记忆文件会被跳过（不阻塞启动）；损坏的 `state.json` 回退默认值。
- **列表上限**：`memory_recall` ≤ 50、`memory_timeline` ≤ 500、`memory_reconstruct` ≤ 20、`/memory-list` 最多显示 200 条（权重最高）。
- **`memory_doctor`**：记录数、各层数量、索引状态、回收站、损坏文件、候选/反馈数量。
- **按必要性暂缓**（不做过度的工程化）：文件锁、fsync、schema 版本迁移、大规模基准、CI 矩阵。

- `memory_recall` / `memory_timeline` 新增 `detail` 参数：默认只返回梗概，`detail: true` 才返回细节记录与 `details` 字段。

**如何测试**：`node test/self-test.mjs`（含「默认召回不含 detail」「detail=true 时召回」）。

### 1. 设置区卡片（唯一 GUI）

**变化**

- GUI 只保留**设置区卡片**：注册到 **设置页左侧「记忆」分区**（`settings.section` 槽，做法参考 `dsh-notify-say`）。
- 卡片内容：顶部「打开记忆文件夹」+「刷新」；下方按**权重（importance）倒序**的记忆列表（层级、日期、内容、来源会话）。右上角不再显示权重数字。
- 数据来源：注册到 **DSH 内置 Web 服务器**的只读路由 `/api/dsh-human-memory/memories` 与 `/api/dsh-human-memory/open-folder`（**不再占用独立端口**）。
- **已移除**：独立网页 GUI（`GET /` 不再返回 HTML）、`/memory-gui` 命令、`memory_gui` 工具。

**为什么还需要一个路由**

卡片运行在 Web 浏览器半，读不到宿主进程内存里的记忆数据。DSH 的 client↔host Remote 在本机版本较复杂，因此用宿主自带的 `webServer.register` 暴露两个只读/低风险路由作为数据通道；不额外开端口。

**如何测试**

1. 重启 DSH。
2. 打开设置页，左侧应出现「记忆」分区。
3. 点「打开记忆文件夹」→ 资源管理器打开 `C:\Users\<你>\.dsh\human-memory\`。
4. 列表应显示记忆，并按权重从高到低。
5. 自动化：`node test/gui-test.mjs`（12 项）。

**预期**：设置页左侧出现「记忆」；按钮可用；列表按权重排序。

### 1.1 删除按钮与删除缓冲区

- 卡片每行右侧新增「删除」按钮；点击**不弹确认**，立即从列表移除。
- 后端把记录**移动到记忆库的 `trash/` 文件夹**（可用 `storage.trashDir` 改名），不再出现在当前记忆区、召回、复习、巩固中；文件保留，方便备份/恢复。
- **下一次巩固时真正删除**（`trash/` 下的文件被移除）；也可通过 `POST /api/dsh-human-memory/restore` 恢复。
- 接口：`POST /delete`、`GET /trash`、`POST /restore`（JSON `{ "id": "..." }`）。
- 自动化：`node test/gui-test.mjs`（17 项，含移入缓冲区、列表隐藏、恢复）、`node test/library-test.mjs`（15 项，含 trash 文件夹、恢复、清空）。

### 2. 工作记忆层（信息量大、细节多、消失快）

**变化**

- 新增 `memories/working/` 目录（`layer: "working"`）。
- 每轮记录**精确操作**：`运行命令：…`、`写文件：…`、`编辑文件：…`、`读取文件：…`。
- 权重刻意很低：`workingMemory.importance`（默认 **0.05**），模拟「快速淡忘」。
- **不设条数上限**：`capacity: 0`（信息量大、细节多、关系乱），靠短 TTL 回收。
- 保留时长：`minRetentionMs` 默认 **24 小时**；且**只在每 24 小时的巩固节点回收**，不会一次全清。
- **召回会刷新 `lastAccessedAt`**，从而把该条工作记忆的清理时间往后推（和复习同思路）。
- **参与召回、复习与巩固**（不再被排除）；复习按「相对保留率」到期，避免低权重记录一上来就刷屏。
- **去重**：同一会话里的同一操作只保留一条，重复发生时刷新访问时间。
- **记录来源会话**：每条工作记忆带 `sessionId`（可选、不强制），避免不同会话混淆。

### 2.1 巩固与回收的节奏（每 24 小时一次）

- 自动巩固**不是每轮都跑**：默认每 **24 小时**一次（`consolidation.intervalMs`）。
- 触发点：会话结束时的检查（到点才执行）、启动后 15 秒检查一次、以及每小时一次定时检查。
- 工作记忆回收与巩固在**同一个节点**执行：只清理「最后一次访问」超过 `workingMemory.minRetentionMs`（默认 24h）的记录。
- 被召回过的记录会刷新 `lastAccessedAt`，因此不会在到期时被清掉，而是顺延。
- 手动 `/memory-consolidate` 或 `memory_consolidate` 会立即执行一次（忽略间隔）。

**分工**

| 层 | 记录什么 | 权重/寿命 |
|----|----------|-----------|
| 工作记忆 `working` | 精确操作（改了哪个文件、跑了什么命令） | 极低权重、短寿命（24h） |
| 情节记忆 `episodic` | 提炼「这一轮做了什么」 | 正常权重 |
| 语义记忆 `semantic` | 巩固后的事实/偏好 | 较高 |
| 核心记忆 `core` | 极重要、长期 | 最高 |

**如何测试**

1. 让 agent 改一个文件或跑一个命令。
2. 打开 `C:\Users\<你>\.dsh\human-memory\memories\working\`，应出现 `<id>.json`。
3. 查看该文件：`importance` 应 ≤ 0.1，`content` 含命令/文件路径。
4. 问一个与工作记录相关的问题，`memory_recall` 应能召回。
5. 自动化：`node test/self-test.mjs`（23 项，含低权重、prune、参与召回/复习/巩固）、`node test/plugin-smoke.mjs`（18 项，含工作记忆落盘）。

**预期**：工作记忆独立成文件、低权重、可被召回/复习/巩固，但在 24 小时后的巩固节点被回收（召回会顺延）。

## v0.1.1 — 2026-10-29

本版针对三条反馈做了改造：**每轮自动自查**、**目录式记忆库**、**事件日期**，并附带**旧版自动迁移**。

| # | 变化 | 涉及文件 |
|---|------|----------|
| 1 | 每轮对话后自动自查并写入记忆（不必每次说「记住：」） | `src/index.js`、`settings.json` |
| 2 | 记忆库从单文件改为目录式（每条记忆独立成文件） | `src/store.js` |
| 3 | 每条记忆记录「事件发生时间」，召回时一并展示 | `src/memory.js`、`src/index.js` |
| 4 | 旧版 `memories.json` 自动迁移到新结构 | `src/store.js` |

- **自动自查**：监听 `session/event` 缓冲每轮文本，`agent/turn-stopping` 时按「长度 / 非提问 / 非问候 / 非注入 / 含信号词」判断写入；参数在 `settings.json` 的 `autoCapture`。
- **目录式记忆库**：`human-memory/index.json` + `human-memory/memories/<layer>/<id>.json`。
- **事件日期**：新增 `occurredAt`，`memory_write` 可传 ISO / `YYYY-MM-DD` / epoch；召回输出带 `[YYYY-MM-DD HH:mm]`；重复提及保留最早时间。
- **迁移**：旧 `memories.json` 自动拆分到 `memories/`，原文件备份为 `.bak`，旧记录补 `occurredAt = createdAt`。
